>>>>>> Block sessions come under Performance issue<<<<<<<


For any block in any prod server we get mails

>why blocks happen?


When there are some long running queries or queries using multiple resources and on top of it there is someone else hitting query on the same db that leads to blockage

For example - All the resources are in use and then someone else is trying to use them but since they are already in use the other one is unable to access them and that creates a block.

It usually happens in case of bulk queries or queries running for a long time


>so when blocked, we can remove that block?


Yes we can if the app team approves
In most cases that i have seen these blocks occur when someone is executing some sp.
Sp uses multiple queries and on top of that someone else also hits queries on the same db
Then due to the ongoing execution of that sp a block is created for the new query hit. 
This also leads to performance issue in sp.
In that case you need to kill the sessions causing blocks

------Query for it is - kill sp_id



>In Non prod, blocks happen less?

But they do happen all the time

>query to check blocks?


Sp_whoisactive
Sp_who2

# Sp_whoisactive
This will give you list of active sessions

# Sp_who2
This will give you list of all the sessions

You can run any but its better to run the first one(SP_whoisactive)

In the result you will get a column as blocking_id under that you can check which session is causing block.
